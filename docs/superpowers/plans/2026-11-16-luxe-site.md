# Luxurious Client Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the client page (`/`) in the approved luxurious, image-led style for every salon, restyle the booking wizard without changing its behaviour, and leave the owner's admin untouched.

**Architecture:** A `site` class on `<html>` (set while a client route is mounted) scopes new fonts, pearl grounds and restyled shared classes (`btn-*`, `card*`, `input`, `label`, `chip-*`, `.font-display`) so the admin, which shares them, keeps its look. Presentation components are rewritten in place (`Navbar`, `Hero`, `Services`, `Philosophy`, `Footer`, `SalonNotFound`); `TrustBadges` is deleted. The booking wizard is restyled through the scoped CSS plus minimal className edits.

**Tech Stack:** Vite + React 18 + TypeScript + Tailwind, Vitest + Testing Library, Google Fonts (Bodoni Moda, Jost, Amiri, Cairo).

**Spec:** `docs/superpowers/specs/2026-11-16-luxe-site-design.md`. Visual reference: branch `spike/luxe-hero` (`git show spike/luxe-hero:src/components/HeroLuxe.tsx`, `ServicesLuxe.tsx`, `NavbarLuxe.tsx`, and its `src/index.css` / `tailwind.config.js` diff). The spike is a reference, not code to copy: it hardcodes photos and copy.

## Global Constraints

- Fonts (client page only): Bodoni Moda (display, weights 400/500 + italic 400, `opsz 6..96`), Jost (text, 300/400/500), Amiri (Arabic display, 400/700), Cairo (Arabic text, as today). Under `.site`: `.font-display` = `'Bodoni Moda', 'Amiri', serif` at weight 400 in **both** directions (so Latin words keep Bodoni in RTL and `font-semibold` classes don't fake-bold it); body/`.font-sans` = `'Jost', 'Cairo', sans-serif` in LTR and `'Cairo', sans-serif` in RTL.
- Colour: add `pearl: { 50: '#FBF9F8', 100: '#F4EFEC', 200: '#E7DFDA' }` to `tailwind.config.js`; brand scale `rose-*` (runtime `--brand-*`) for deep fields and text; champagne = existing `gold-200` (fills) and `gold-700` (text on pearl). No raw hex in components.
- Shape: buttons and inputs `rounded-[2px]`; no shadows on cards; separators `border-rose-900/10`.
- Motion: only the hero load moment (photo `scale(1.06)→1` over 2.4 s; name then lines rise 14 px with fade, delays 0.25 s / 0.6 s); all disabled under `prefers-reduced-motion: reduce`.
- Never: tracked all-caps labels, numbered markers, middle-dot meta strings, `→` appended to labels, card shadows, per-section fade-ins.
- Every user-facing string through `t()` with keys in **both** `fr` and `ar`; logical CSS (`ms/me/ps/pe/text-start/end`); lucide-react icons only; content photos through `SmartImage` or a plain `<img>` with `alt`, read via `photoUrl`/`fetchServices` (already applied by `useServices`).
- The admin (`/admin*`) must look exactly as before: nothing outside `.site` changes except added tokens.
- No change to the booking wizard's steps, state, RPC calls, error handling or copy keys; no database or RPC change.
- `pnpm check:bundle` must pass **without** editing `scripts/public-bundle-baseline.json` (cap 195 KB; was 194.1 KB). Run `pnpm build && pnpm check:bundle` at the end of every task and write the KB figure in the commit message body.
- Every touch target ≥ 44 px; visible keyboard focus on every link/button.

## Review Focus
